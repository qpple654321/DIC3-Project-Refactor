# 02 — A–F, Five Core Principles, Three Trade-offs, Ten Technical Details

**Research question:** Can an LLM produce a motorcycle touring itinerary that is *executable*, not merely plausible?

## A–F abstract framework

**A — Attention Getter / Problem.** LLM itineraries may look persuasive but violate hard constraints. Existing general travel benchmarks expose this gap; motorcycle touring adds weather exposure, daylight windows, fuel range and rider-specific pacing.

**B — But / Research Gap.** General navigation uses population-level estimates. Route-centric motorcycle apps and general LLM travel benchmarks do not jointly evaluate the *arrival-time-dependent* compatibility of rider pacing, station opening hours, weather alerts and road closures.

**C — Cure / Proposed Solution.** Moto Touring Copilot combines multi-agent coordination, private GPX-based time quantiles, official-source grounding and an independent deterministic verifier in a Generate–Verify–Repair loop.

**D — Development / Technical Plan.** Five agents orchestrate trip understanding, pacing, weather, road/supply and verification. Segment movement-time P50 with trip-level conformal P90 underpins ETA windows. Five verifiable rules decide acceptance or replanning.

**E — Experiments / Validation.** E1 compares travel-time baselines and personalized models. E2 uses an independent oracle for LLM-only, grounded-LLM and full-system ablations. E3 replays historical warnings/closures where archives exist. E4 examines 2–3 representative rides.

**F — Findings / Expected Outcomes.** Expect more accurate rider-specific timing, fewer constraint violations and stronger provenance, but these are hypotheses, not results. Avoid unmeasured percentages or accident-reduction claims.

## Five core domain principles

1. **Segment-specific pacing:** plan for challenging curves/slopes, not a crude average speed; use trip-calibrated P90.
2. **Weather by ETA:** query forecast/warnings for where and when the rider reaches each segment.
3. **Daylight as a hard window:** conservative arrival must precede civil twilight end or rider cutoff.
4. **Fuel by open-at-arrival availability:** stations must be reachable with reserve *and open when reached*.
5. **Road states change:** closures/restrictions invalidate candidates, requiring clear feedback and replanning.

## Three engineering trade-offs

| Trade-off | Decision | Evaluation |
|---|---|---|
| P90 conservatism vs route flexibility | Calibrate whole-trip P90 with held-out trips, not sum segment P90 naively | Coverage, refusal and feasible-option rates |
| Authoritative data freshness vs API availability | Fail explicitly on stale/missing required inputs; never fabricate | Source-failure scenarios |
| Personalization vs location privacy | Keep raw GPX private; trim sensitive endpoints before derived exports | Privacy and leakage tests |

## Ten technical details

| # | Detail | Specification |
|---|---|---|
| 01 | Input requirements | Trip date, waypoints, rider deadline, vehicle/range, user preferences |
| 02 | GPX ingestion | Remove sensitive endpoints, clean GPS anomalies, separate stops from movement |
| 03 | Route segmentation | ~0.5–2 km or topology-aware segments |
| 04 | Features | Curvature, DTM terrain grade, road classification, caution labels |
| 05 | Pacing model | Log moving-time regression, LightGBM quantile P50/P90 |
| 06 | Interval calibration | Trip-level conformal correction, held-out ride calibration |
| 07 | Weather/daylight tools | CWA forecast, warnings and civil twilight end for ETA windows |
| 08 | Road/fuel tools | TDX closures; fuel points, hours, conservative arrival, range reserve |
| 09 | Verification and replan | Deterministic R1–R5, bounded retries, violations and provenance |
| 10 | Independent experiments | E1 GroupKFold + temporal split; E2 oracle; E3 history; E4 case studies |

## Three falsifiable hypotheses
**H1:** Hybrid verification produces higher all-hard-constraint pass rate than LLM-only.  
**H2:** Grounded authoritative data reduce infeasible itineraries versus otherwise matched ungrounded planning.  
**H3:** Replanning improves disruption recovery compared with static itineraries.

**Measured indicators:** final pass rate, per-rule/micro pass rate, refusal rate, MAE/MAPE, trip P90 coverage, daylight violations, fuel-point coverage, source traceability and replanning success.
